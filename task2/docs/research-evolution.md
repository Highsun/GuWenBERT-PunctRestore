# 任务二研究路线与方法演进

整理日期：2026-10-17。记录范围：v0.1～v0.5 已完成实验，以及后续待验证方向。

本文记录各阶段的研究问题、方案依据、关键选择和实验结论，供最终报告组织方法演进与讨论。各阶段设计文件保留实施前的假设和对照，结果文件记录实际测量；后续结果不回写早期假设。

## 1. 从句号推进到独立批量窗口

题目给出的基础方法以预测句号确定下一窗口起点。同一文章的后续输入依赖前一窗口输出，直接逐窗执行时难以发挥 GPU 批处理能力。v0.1 因而先将核心区间按 token 预算提前划定，再补充左右上下文，使窗口在预测前即可独立构造。

核心区覆盖原文且互不重叠，最终只提交核心标签；上下文提供局部语义，字符到 token 的映射保证输出可以还原到原文位置。固定窗口与同窗 batch=1 对照用于测量批处理本身的收益，句号推进串行对照用于评价完整工程方案的取舍。

256/192/31、batch=16 的初版在重建测试长文上取得 68.476% micro-F1，相对对应句号串行加速 9.57 倍。同窗 batch 加速为 8.92 倍。400/300/49 也取得加速，但当前冻结模型下质量较低。固定窗口实现了解耦，交界处上下文是否充足仍需后续实验回答。

设计与结果：[初版汇总](../reports/initial-summary.md)。

## 2. 用训练句长确定上下文候选

最初的 H=31、49 来自给定窗口与核心预算的余量分配。为使上下文选择有语料依据，v0.2 从清理后的训练集统计完整句末区间长度，以中位数、均值和分位数构成候选，再增加零上下文及原始预算对照。

122,601 个句段的长度中位数为 14 token，均值约 18.30，P90 为 34，P95 为 42，P99 为 66。实验同时比较固定总窗与固定核心：前者反映实际质量和计算量取舍，后者保持交界位置，控制切点变化的影响。

固定核心 192 时，H=14 相对 H=0 的总体 micro-F1 提高 1.552 个百分点，交界区域提高 20.018 个百分点；H=8～66 的总体变化较小，H=96 下降。固定总窗 256 时，H=49 的开发集分数最高。由此保留两类候选：中位数配置用于较低重复计算成本，H=49 配置用于检验开发集高分是否能推广。

设计与结果：[预算实验设计](../reports/cclue-context-budget-v0.2/design.md)、[结果分析](../reports/cclue-context-budget-v0.2/conclusions.md)。

## 3. 将上下文选择与 batch 扩展结合

v0.3 比较四种窗口及 batch=1/4/8/16/32/64。参数选择优先采用接近最快耗时的较小 batch，并限制数值质量漂移；先保存开发集选择，再评价测试集，避免按测试分数选择 batch。

222/192/14 选定 batch=32，其余三种窗口选定 batch=16。64 虽可运行，但没有成为最快条件。中位数方案测试 micro-F1 为 68.509%，中位耗时 2.142 秒，对应串行加速 10.88 倍。256/156/49 测试为 68.493%，开发集高分优势未得到明确确认，耗时则高于原窗口。

这一阶段形成速度优先候选 median222-b32，并说明可用显存并不直接决定最佳 batch。不同 batch 形状导致的少量 BF16 标签差异单独记录，没有解释为模型能力提升。

设计与结果：[Batch 实验设计](../reports/cclue-batch-scaling-v0.3/design.md)、[结果分析](../reports/cclue-batch-scaling-v0.3/conclusions.md)。

## 4. 利用已有重叠预测改善质量

核心输出会丢弃其他窗口对同一字符的预测。v0.4 保留各窗概率，比较核心概率控制、等权融合及中心加权融合；模型、窗口和 batch 不变，以控制额外模型计算。

等权融合使窗口边缘预测与中心预测具有相同贡献，两种窗口的总体质量均下降。中心加权降低边缘贡献，开发集从线性和平方权重中选定线性权重。256/192/31、batch=16 的测试 micro-F1 达到 68.652%，相对同窗核心输出提高 0.176 个百分点，增益区间为 [0.087, 0.243]，耗时增加 5.13%。

初始实现每窗重复转换全文 token 索引，产生较大的主机成本。优化后仅处理窗口内索引，等权方案直接使用全一权重；两轮开发集的概率和预测完全一致。初始实现与优化实现分别保留，避免将算法收益与实现开销混在一起。

这一阶段形成质量优先候选 original256-weighted1。其相对串行的微小质量差值区间包含零，已确认的质量改善来自与同窗核心输出的比较。

设计与结果：[融合设计](../reports/cclue-window-fusion-v0.4-optimized/design.md)、[结果分析](../reports/cclue-window-fusion-v0.4-optimized/conclusions.md)、[初始实现记录](../reports/cclue-window-fusion-v0.4/pilot-note.md)。

## 5. 将额外计算分配给疑难交界

v0.5 研究能否只复核少量交界改善质量。第一遍采用已验证线性融合，按不确定性或跨窗分歧筛选交界，第二遍围绕交界居中，只替换左右各 8 字符。逐文档同预算随机复核用于区分筛选价值与新增计算本身，全量复核作为诊断对照。

开发集比较名义 10%、25%、50% 预算，按预设质量容差和耗时规则锁定 disagreement-10。测试实际选择 162/2,077 个交界，micro-F1 为 68.650%，相对无复核 68.652% 的差值区间包含零，耗时增加 10.16%；相对随机复核也未确认总体 F1 优势。

分歧选区的基线标签错误率为 14.04%，随机选区为 8.05%。第二遍修正 78 个错误，也将 83 个原本正确的标签改错，修正收益被抵消。当前结果支持继续研究复核预测的使用方式；尚不能认定提高复核预算能够改善质量。

设计与结果：[复核设计](../reports/cclue-selective-review-v0.5/design.md)、[结果分析](../reports/cclue-selective-review-v0.5/conclusions.md)。

## 6. 当前保留的方法与后续问题

| 定位 | 配置 | 当前依据 |
| --- | --- | --- |
| 速度优先 | 222/192/14、batch=32、核心输出 | v0.3 测试耗时较低，micro-F1 为 68.509% |
| 质量优先 | 256/192/31、batch=16、线性中心融合 | v0.4 相对同窗核心取得小幅质量增益，micro-F1 为 68.652% |
| 基础参考 | 256/192、batch=1、句号推进 | 保留老师基础方法的质量与效率对照 |
| 负结果与诊断 | 等权融合、直接替换式复核 | 完整保留，不作为当前推荐方案 |

后续按以下顺序推进，各阶段使用独立设计、编号和源码快照：

1. 利用已有概率缓存比较复核软融合和条件接受，检验新增错误能否减少。先固定 v0.5 的交界筛选与预算，再改变合并规则。
2. 实现跨文档动态批处理的句号推进。不同文章可在同一 batch 独立推进，形成更强的工程 baseline；单篇长文内部仍有依赖。
3. 分析 GPU 聚合、数据传输与编译执行成本，分开记录冷启动和预热后性能。
4. 探索重叠区自适应拼接，仅在已有窗口预测上选择输出切换位置，避免重新引入构窗依赖。

以上四项在本次整理时尚未实施。所有后续测试均应先锁定开发集选择。当前研究多次使用同一测试集，最终泛化验证还需新增来源明确的外部长文留出集。任务一保持冻结，当前路线均围绕任务二推理展开。
