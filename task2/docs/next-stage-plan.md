# 下一阶段实验计划：跨窗口概率融合

整理日期：2026-10-17。状态：待实施。

## 研究问题

固定并行窗口已实现明显加速，但交界附近仍存在误差。当前只输出字符所属核心窗口的 argmax 标签；下一阶段拟利用重叠窗口对同一字符的多次概率预测，研究融合能否改善质量，以及概率保留、聚合和传输带来的额外成本。

跨窗口融合仍受每个窗口的上下文限制，不能恢复窗口外的完整语义依赖。本阶段首先研究局部重叠信息的利用，不更换模型或重新训练。

## 候选对照

| 方案 | 输出方法 | 比较目的 |
| --- | --- | --- |
| 现有核心输出 | 字符只采用其所属核心窗口的预测 | 已验证的固定并行对照 |
| 等权概率融合 | 对覆盖同一字符的窗口概率取均值 | 测量利用多窗预测的直接效果 |
| 中心加权概率融合 | 按字符距窗口边缘的位置分配权重，再聚合概率 | 研究降低窗口边缘预测影响是否有效 |
| 串行句号推进 | 按预测句号决定下一起点 | 保留题目给出的工程参考 |

优先使用 median222-b32；original256-b16 保留为第二种窗口对照。对比核心输出与融合时保持模型、窗口位置、输入 token、batch、精度和数据完全相同，使差异集中在概率解码与聚合方法。融合权重及其参数在实际实施前写入新的设计文件。

## 评价与选择

先在既有开发集重建长文上比较总体标点 micro/macro-F1、任意标点断句 F1、句末边界 F1，以及相同交界位置附近的质量。分别记录窗口数量、前向次数、概率聚合耗时、端到端耗时、传输量和显存峰值。预热后随机排序重复计时，按文档组计算配对质量差值区间。

融合方案应与保留概率但不融合的控制实现比较，以区分输出概率本身的开销和融合算法的开销；同时与现有只传整数标签的实现比较，报告实际部署代价。验证每个字符完整输出、覆盖次数与权重和正确，避免将多窗重复预测当作多个计分样本。

开发集选择规则在正式测量前确定。参数锁定后只运行选定方案的测试集评价，不根据测试分数继续调参。若质量改善不足或成本过高，保留负结果，不以开发集最高分代替测试验证。

## 版本与实验边界

使用新的实验编号，建议从 `cclue-window-fusion-v0.4` 开始。现有核心输出和串行路径作为对照保留，融合通过独立实现接入，不改写 v0.1～v0.3 的报告与运行产物。任务一继续只读复用。
