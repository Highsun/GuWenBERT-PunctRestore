# 任务二：长文本批量滑窗推理

当前仅有初始化骨架，未开始推理实现或性能实验。实施时以任务一已经完成并冻结的模型为输入。

## 范围与目录

本任务负责串行滑窗基线、批量滑窗、重叠区合并及质量和性能对照。两种推理方法均实现在本任务内，不为实现基线而修改任务一。

源码位于 `src/guwenbert_task2/`，配置、命令入口和必要测试分别放入 `configs/`、`scripts/` 和 `tests/`。依赖由本目录的 `pyproject.toml` 和 `uv.lock` 管理，后续进入本目录执行 `uv sync --locked` 时使用本目录 `.venv/` 和 `.cache/uv/`。当前没有机器学习依赖或可运行入口。

只读使用任务一冻结的 `models/task1/<版本>/`、数据划分和标签契约。新增的评测数据放入 `data/processed/task2/<版本>/`、`data/splits/task2/<版本>/`，新增模型产物如有需要放入 `models/task2/<版本>/`，所有运行结果写入 `outputs/task2/<运行编号>/`。路径均相对于项目根，执行脚本时须显式解析，不依赖启动时的工作目录。

## 报告与边界

实验报告和精简的对照指标写入本任务的 `reports/`。记录任务一冻结标签、模型和数据校验值，以及 batch、窗口、重叠、精度、硬件、质量、显存、吞吐量和耗时，便于与任务一报告分别引用。

不直接导入任务一源码，不修改任务一的源码、配置、锁文件、数据版本、模型、报告或既有运行结果。依赖升级仅修改本任务的声明和锁文件。若发现任务一问题，单独提出修正并形成新版本，之后显式决定是否切换所用模型版本。

完整交接规则见 [任务边界与冻结流程](../docs/task-boundaries.md)。
