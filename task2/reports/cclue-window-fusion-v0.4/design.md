# 跨窗口概率融合实验设计

日期：2026-10-17。编号：`cclue-window-fusion-v0.4`。模型为任务一冻结的通用中文 BERT，不重新训练。

## 实验条件

使用 median222（总输入 222、核心 192、每侧上下文 14、batch=32）和 original256（256/192/31、batch=16）。前者保持固定核心划分，后者沿用初版短文整窗规则。每个窗口方案比较核心整数标签、保留概率的核心输出控制、等权概率融合、线性中心加权和平方中心加权，共 10 个固定条件；另加入 256/192 的句号推进串行方法，共 11 个开发集条件。

模型、窗口位置、输入、batch 与 BF16 精度保持一致。整数标签方案复用原实现；概率方案只保留各字符首个 subtoken 的八类概率，softmax 使用 FP32，主机聚合使用 FP64。所有概率方案均保留同样的概率数组，以控制数组保存开销；详细缓存写出在计时后完成。

## 融合公式

字符 i 在窗口 j 中的概率为 p(j,i,k)，k 为八类标签。权重按完整字符的 token 边界计算。窗口正文 token 数为 L，字符首个 token 的零基位置为 a，末尾边界为 b，则 d=min(a,L−b)+1，中心权重为 w=(d/ceil(L/2))^α。α=1 为线性，α=2 为平方；等权融合取 w=1。

最终概率为各窗口的 Σ(w·p)/Σw，再取 argmax。权重始终为正，不会遗漏窗口端点。核心概率控制组仅让字符所属核心窗口贡献权重 1，验证其与整数标签核心输出完全一致。所有窗口的概率指纹应一致，确保融合对比只改变聚合规则。

## 数据与参数选择

开发集沿用 185 个匿名文档组、341,563 字符；测试集沿用 180 组、417,786 字符。每种窗口方案分别在 α=1、2 中选择五次预测稳定的候选，以开发集标点 micro-F1 为主；在距最高分不超过 0.02 个百分点的候选中，选择中位耗时较低者，完全相同则选较小 α。等权融合是预设对照，不参与 α 选择。

选择记录保存后，测试各窗口的核心整数输出、核心概率控制、等权融合及选定的加权融合，另保留串行参考，共 9 个条件。测试结果不用于再次调参。工程可用性另要求：测试总体增益的配对 95% 区间下界大于零，且相对核心整数输出中位耗时增加不超过 15%；未达到条件时保留结果，不认定融合改进成立。

## 测量与验证

每条件预热一次，随机排序正式测量五轮。端到端包含编码、构窗、排序、padding、传输、模型、概率计算、聚合、argmax 和文本恢复，排除模型/数据读取、计分、文件校验、指纹计算与结果写出。单独记录 GPU 前向事件、概率计算事件、概率 D2H 字节、主机等待及拷贝时间和聚合时间。D2H 等待包含此前 GPU 工作的同步等待，不与 GPU 事件时间直接相加。

报告标点 micro/macro-F1、任意标点断句 F1、句末边界 F1、相同核心交界区域、内部及片段连接附近的质量。按文档组进行 2,000 次配对 bootstrap，未作多重比较校正。保存逐字符预测、窗口索引、概率缓存、覆盖次数与权重和；独立从缓存复算融合结果，检查每个字符最终输出一次，重叠预测不作为重复计分样本。

保留前几轮报告、代码与运行产物，运行前后核对已验收校验值和任务一冻结文件。本轮只研究局部重叠预测的利用，不能恢复单窗外的完整语义依赖。
