# 任务二阶段总结：滑窗设计、上下文预算与批量推理

整理日期：2026-10-17。当前完成至 `cclue-batch-scaling-v0.3`。

## 1. 工程目标与实现

任务二针对 BERT 输入长度限制，研究古文长文本断句标点的高效推理。使用任务一 `task1-v2.0` 冻结的通用中文 BERT 主模型，不重新训练。任务二的源码、配置、测试、uv 环境及报告独立保存，通过模型文件和推理契约读取任务一产物。

已实现三种对照：句号推进串行方法、固定窗口 batch=1、固定窗口批量推理。串行方法在每窗预测后，按推进预算内最后一个预测句号决定下一起点。固定方法预先划分互不重叠的核心区间，两侧重叠部分提供上下文；每个字符只由一个窗口负责输出，窗口位置不依赖前窗预测，因此能够提前组 batch 并行计算。

全文字符编码一次，窗口复用编码；字符与 token 保持对齐，多 subtoken 字符完整保留，仅使用首个 subtoken 的标签。窗口按长度排序，batch 内动态 padding 至 8 的倍数，使用 BF16、SDPA 和 inference mode。预测按原字符位置恢复，不强制补充文末句号。每批整数标签统一传回主机。

## 3. 数据与上下文预算结论

训练集仅用于句长统计，得到 122,601 个相邻句末间的完整跨度。句长均值为 18.30 token，中位数 14，P95 为 42，P99 为 66。各连续区间首个缺少左边界的跨度和末尾不完整跨度排除，不跨文档或清理后的记录缺口连接。

开发集由 4,074 条原始片段重建为 185 个匿名文档组，共 341,563 字符；测试集由 3,992 条片段重建为 180 组，共 417,786 字符。文档组是工程评价单位，保留原片段区间与连接位置，不代表已恢复完整古籍原始排版。

固定核心为 192、切点保持一致时，每侧上下文从 0 增至 14 token，总体标点 micro-F1 从 64.213% 提高到 65.765%，交界左右各 8 字符区域从 44.122% 提高到 64.140%。总体增益为 1.552 个百分点，文档级配对 bootstrap 95% 区间为 [1.277, 1.802]。

H=8～66 时总体分数范围约为 0.104 个百分点，H=96 时下降。H=14 相对原预算 H=31 的增益只有 0.093 个百分点，差值区间包含零。因此，句长统计能够为候选上下文提供依据，但不能直接决定最优预算。

## 4. Batch 扩展及测试集结果

v0.3 在开发集选择 batch 后锁定参数，再运行本轮测试。选择要求五次预测一致，micro-F1 相对本方案 batch=16 的漂移绝对值不超过 0.02 个百分点；在合格条件中选择中位耗时距最快值不超过 3% 的最小 batch。该规则用于控制数值漂移及资源成本，不是统计等效性检验。

| 选定方案 | 总预算/核心/每侧上下文 | batch | 测试 micro-F1/% | 中位耗时/s | 同窗 batch=1 加速 | 对应串行加速 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| original256 | 256/192/31 | 16 | 68.476 | 2.348 | 8.90× | 9.92× |
| median222 | 222/192/14 | 32 | 68.509 | 2.142 | 9.97× | 10.88× |
| quality256 | 256/156/49 | 16 | 68.493 | 2.837 | 8.89× | 8.21× |
| teacher400 | 400/300/49 | 16 | 67.630 | 2.519 | 5.12× | 5.40× |

前三种方案对应 256-token 串行参考：micro-F1 为 68.633%，中位耗时为 23.291 秒。teacher400 对应 400-token 串行参考：68.026%、13.589 秒。输入预算包含两个特殊 token；median222 的 tensor 补齐至 224，但只按 222 的逻辑预算读取正文。

median222-b32 吞吐约 195,079 原文字符/秒，峰值已分配显存约 0.726 GiB。相对对应串行方法，micro-F1 低 0.124 个百分点，配对 95% 区间为 [−0.299, +0.020]。相对 original256-b16，中位耗时降低约 8.8%，质量差值为 +0.033 个百分点，区间为 [−0.125, +0.163]。它可作为下一阶段优先候选，原方案保留为对照；当前结果尚不足以确认质量提升。

quality256 的名称来自其开发集高分表现。H=49 相对原预算 H=31 的开发集增益没有在测试集上得到明确确认，测试增益仅为 0.017 个百分点，耗时增加约 20.9%。扩大到 400-token 输入在当前模型上也没有带来质量优势。

batch=64 均能运行，但没有取得各方案的最佳整体耗时。峰值已分配显存低于 1.2 GiB，前向与 argmax 的 GPU 事件时间也在 batch=16～32 附近趋于平稳。显存仍有余量不能单独作为继续扩大 batch 的依据。

## 5. 验证、保存与复现

当前 34 项工程测试通过，覆盖字符与 token 对齐、窗口完整覆盖、核心区间、句长连续性、配对抽样及 batch 选择规则。初版还完成四个模型导出参考案例核对、3,200 字长输入覆盖和原始短片段质量回归。

v0.3 全部 36 个条件通过字符覆盖、混淆矩阵独立重算、窗口一致性、预测指纹、原始计时及 bootstrap 区间核验。不同 batch 形状下可能出现少量 BF16 标签差异，单个条件的五次预测均一致，不将数值漂移解释为模型能力提升。

任务一冻结文件、初版产物和已验收的上下文预算结果保持一致。参数选择记录、各阶段配置、依赖锁文件、数据与模型校验值、报告及图表纳入本次 Git 提交。原始及派生语料、模型、虚拟环境、缓存、逐字符详细预测和完整运行目录继续在本地保存，不纳入 Git；仅克隆代码仓库不足以恢复这些运行输入。

两组扩展实验共生成 10 张图，每张提供 300 dpi PNG、SVG 和 PDF，共 30 个图像文件。计时均为模型及字符编码缓存预热后的端到端耗时，包含编码、构窗、排序、padding、传输、前向、argmax、解码和文本恢复，排除模型/数据加载、文件校验、计分和结果写出。

## 6. 下一阶段准备

下一阶段重点是降低固定并行窗口的交界误差，同时保留批量吞吐优势。候选方向为跨窗口概率融合，先在开发集比较融合方式的质量和额外成本，再锁定参数进行测试。median222-b32 和 original256-b16 保留为当前对照，老师的串行方法继续作为工程参考。

本轮只整理下一阶段设计，不新增融合代码、不启动新实验。后续运行使用新的实验编号与结果目录，现有报告和原始测量保留。具体方案见[下一阶段实验计划](../docs/next-stage-plan.md)。
