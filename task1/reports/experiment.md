# 任务一实验报告：人民日报 9801 上的 GuwenBERT 微调

本报告来自完整真实运行，日期为 2026-10-15（Asia/Shanghai）。仅研究七类常用标点恢复，未开展任务二的滑窗效率实验。

## 数据与划分

使用 `data/raw/199801.txt`；2—6 月文件未参与本次训练或测试。共有 3,148 篇源文章，按去标点正文 SHA-256 去除 2 篇重复文章，保留 3,146 篇；重复文章中标签冲突数为 0。种子 42，按文章随机分组后以约 80%/10%/10% 划分，随后再切分为互不重叠的 token 窗口。验证集用于选模型，测试集只在训练完成后用于最终评测。

| --- | ---: | ---: |

| validation | 314 | 166,071 |
| test | 316 | 178,882 |

先去掉行号、词性标签和组合词包装，连接文章内各行，再构建“字符后标点”标签。标签为 `O` 与 `，。？！；：、`。ASCII 对应标点映射为中文标点；数值内部的中英文小数点、分数斜线和百分号保留。引号、括号、书名号、破折号等不在输出标签范围内，删除并计数；连续目标标点合并为一个标签，句末标点优先，否则取最后一个。源数据检查记录 12 次合并事件。完整审计与校验值见 `results.json` 及本地数据清单。

原始文件未重写。3 月已知的 U+0016 不在本次 1 月语料中；解析器会记录并删除派生文本中的控制字符，不修复或覆盖原始文件。文章分组和整篇正文去重避免了窗口或完全相同文章跨集合；没有执行近重复检索，不能排除部分重复段落或转载片段。

## 模型与训练

采用 [ethanyt/guwenbert-base](https://huggingface.co/ethanyt/guwenbert-base) 的预训练编码器，新增八类 token 分类头并微调全部参数。其模型卡声明 Apache 2.0 许可，并说明其在古文上继续预训练；本次未使用作者已训练的标点恢复模型。固定上游提交为 `eff0d4a5196d7bf7b8be746c5c6437e89d8b9061`。

每个 Unicode 字符独立经 tokenizer 编码，监督其第一个 subtoken，其余 subtoken、特殊 token 与 padding 使用 -100 忽略；无编码字符以 UNK 占位。窗口按实际 token 数装箱，不按字符数直接截断，长度上限 256，包含 CLS/SEP；所有字符恰好监督一次。

训练 3 轮，batch=16，评测 batch=32，AdamW 学习率 3e-05、weight decay=0.01，warmup 比例 0.1，线性衰减，梯度裁剪 1.0，精度 bf16。以验证集标点 micro-F1 最高的 epoch 保存模型，不用测试集选 checkpoint。没有重采样或类别权重。

硬件：NVIDIA GeForce RTX 5070，设备显存 11.91 GiB；Python 3.12.15，PyTorch 2.9.1+cu128，Transformers 4.57.6，CUDA runtime 12.8。训练窗数 6,481，验证窗数 819，优化步数 1,218；耗时 109.26 秒（含逐轮验证及最佳模型导出），PyTorch 峰值已分配显存 2.95 GiB、峰值保留显存 3.20 GiB。时间边界已做 GPU 同步，不含模型下载及数据预处理。显存指标不等同于整机或驱动的总占用。

## 独立测试结果

加载导出的最佳 checkpoint（epoch 3）后，对 316 篇测试文章、866 个互不重叠窗口、178,882 个字符计分。测试窗末尾保留原始字符标签，不人为补句号。测试流程耗时 1.49 秒，包含预测保存，不作为任务二的吞吐量基准。

- 标点 micro precision / recall / F1：0.6987 / 0.6806 / **0.6895**。
- 七类标点 macro-F1：**0.4898**，按固定七类等权平均，零分母计 0。
- 句末边界 precision / recall / F1：0.7022 / 0.7620 / **0.7309**。
- 含 O 的字符准确率：0.9598；全部预测 O 的基线准确率为 0.9156，标点 F1 为 0。

## 适用范围与局限

该结果是现代新闻语料同月留出测试，不能替代古文标注集上的评测。本次没有可靠的独立古文测试集，因此不报告古文质量指标。单次种子、单次配置实验不能用于说明所有配置或数据上的最优性；稀有标点的支持数较少，须结合各类指标阅读结果。

只恢复七类标点，不能还原原始引号、括号或连续标点的完整形式。数据规范化会删去非目标标点，因此这里衡量的是规范化后的目标任务。字符独立分词保证位置可追溯，但与预训练时的整句分词不同，尤其可能影响拉丁文本和未知字符。

任务一演示仅允许一个 token 窗口；多千字文本的滑窗、批量推理与效率对照留给任务二。标准 `save_pretrained` 模型、tokenizer、`labels.json` 和 `inference_contract.json` 已导出到 `models/task1/pd9801-guwenbert-v1`，可通过 Transformers 独立加载；字符对齐和规范化契约需一并遵守。
