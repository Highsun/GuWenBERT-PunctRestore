# 任务边界与冻结流程

任务一已获授权迁移为 v2：通用中文 BERT 在 CCLUE 古文数据上微调，GuwenBERT 作同数据对照，完成真实训练与测试后用新标签 `task1-v2.0` 冻结。旧标签 `task1-v1.0` 保留，旧本地语料和运行产物按用户要求删除。任务二仍仅有初始化骨架。

## 独立工作范围

| 项目 | 任务一 | 任务二 |
| --- | --- | --- |
| 代码与入口 | `task1/src/`、`task1/scripts/` | `task2/src/`、`task2/scripts/` |
| 配置与测试 | `task1/configs/`、`task1/tests/` | `task2/configs/`、`task2/tests/` |
| Python 依赖与环境 | `task1/pyproject.toml`、`task1/uv.lock`、`task1/.venv/` | `task2/pyproject.toml`、`task2/uv.lock`、`task2/.venv/` |
| 模型与运行结果 | `models/task1/`、`outputs/task1/` | `models/task2/`、`outputs/task2/` |
| 实验报告与精简元数据 | `task1/reports/` | `task2/reports/` |
| 核心结论 | 微调和独立测试的效果 | 串行与批量滑窗的质量和效率对照 |

原始语料及其清单可以共享，但只读。派生数据和划分按任务与版本分目录。任务二可以只读复用任务一冻结的数据，不覆盖原有版本。根目录仅保存仓库说明、原始数据清单和跨任务约定，不承载会同时影响两个任务的业务实现。

两个任务使用独立 uv 项目，不建立共享依赖锁文件的 workspace。不直接跨任务导入源码，也不引入未经冻结的共享业务模块。确实需要复用的逻辑，应通过稳定的文件契约交接；若未来采用共享软件包，必须明确版本并锁定，不能使用可变的相对源码路径。

## 任务一冻结条件

任务一获得实施授权并完成后，再执行以下流程：

1. 完成真实训练、独立测试及必要验证，整理 `task1/reports/` 中的实验报告。
2. 固定任务一代码、Python 版本、依赖声明和锁文件，记录训练与测试配置、随机种子及硬件环境。
3. 记录原始数据清单、派生数据和划分的版本及校验值，固定标签定义、预处理规则和计分规则。
4. 导出用于推理的模型、tokenizer、模型配置和标签映射，记录文件路径、大小和 SHA-256。权重、数据及详细运行结果在本地按版本保存；Git 标签不会自动备份这些被忽略的文件。
5. 提交报告和精简冻结清单后，对已验证的提交创建明确标签，例如 `task1-v2.0`。标签标识代码及文档版本，冻结清单标识本地模型和数据版本。后续版本不得覆盖原标签。

冻结后不移动或覆盖原标签。任务二开发期间不改写任务一目录及冻结产物。必要修正作为任务一单独的新版本完成验证，创建新标签，并保留旧标签、产物和报告；任务二显式记录使用哪个版本。

同一仓库下的目录约定与 Git 标签用于隔离和追溯，不等同于文件系统写保护。后续实际实施时，在任务二每轮改动和评测前后核对任务一目录差异及冻结产物校验值。

## 模型与数据交接契约

任务一应交付能由任务二独立加载的模型文件与明确的文件格式，避免任务二运行时依赖任务一源文件。具体格式在选定模型和标签后确定，至少包含：

- 模型结构/配置、权重、tokenizer 文件及所需软件版本。
- 标签 ID 与标点的映射，无标点及连续标点的表示方式。
- 字符与 token 的对齐、特殊 token、空白和未知字符的处理规则。
- 输入、预测输出与评测样例的格式，数据划分版本及计分规则。
- 代码标签、文件校验值和必要的小规模参考预测，用于任务二核对独立加载结果。

任务二通过这些文件独立实现加载、串行基线和批量滑窗，不通过调用任务一内部脚本来绕过边界。对照实验固定同一模型、标签和测试输入，并分别保存配置与结果；推理策略可以不同，质量差异应如实报告。

## 报告归属

任务一报告说明数据制备、微调设置、独立测试和冻结版本；任务二报告引用任务一的冻结版本，说明长文本方案、边界处理与质量/性能对照。两个任务均记录 Git 版本、依赖锁文件、数据及模型版本和运行产物位置，原始结果不混写到同一运行目录。
